# Starter `accept.txt` for a Vale vocabulary (`Vocab = …` in vale.ini).
#
# Vale's built-in `Vale.Spelling` check uses a general dictionary, so it flags
# ordinary technical jargon as misspelt. Without a seeded vocabulary the first
# run in a docs repo buries every real style finding under spelling noise --
# 190 alerts across this plugin's own tree before this list existed.
#
# It does NOT need British/American spelling pairs: Vale's dictionary accepts
# both (`behaviour`, `organisation`, `initialise`, `licence`, `catalogue` pass).
# Only jargon belongs here.
#
# CONVENTION -- each line is a regular expression, and `Vale.Terms` then requires
# the term to appear EXACTLY as written. A bare `citability` therefore accepts the
# lowercase word but reports `Citability` at the start of a sentence or heading.
# So write common nouns case-tolerantly, and collapse simple plurals:
#
#     [Cc]onfigs?     accepts config, Config, configs, Configs
#     READMEs         a fixed capitalisation, left exact on purpose
#
# `/docs-lint-setup` copies this file. Append the repo's own product names,
# domain terms, and cited proper nouns beneath it -- taken from prose already in
# the repo, never invented. Give a product name its exact capitalisation so
# `Vale.Terms` enforces it (`GitHub`, not `[Gg]ithub`); that is the rule working
# for you rather than against you.
